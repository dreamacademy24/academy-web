# 공통 학생 화면과 방문별 교사 배정

## 현재 범위

- 한국인 관리자 메뉴의 `학생 케어 · 방문 이력`과 Teacher Hub의 `My Students`는 `/staff/students`로 연결한다.
- 원본 명부에서 신원을 확인해 연결한 care_learners/care_visits만 표시한다. 아직 연결하지 않은 예약 학생은 자동 노출하지 않는다.
- 관리자는 학생 이름 검색, 담당자 미배정 필터, 학생별 방문 목록, 방문별 복수 선생님 배정/해제, 배정 변경 이력을 이용한다.
- 현지 선생님은 활성 배정이 있는 방문만 조회한다. 같은 학생의 다른 방문 접근은 자동 부여하지 않는다. 이전 방문의 리포트 인계 범위는 리포트 기능 단계에서 별도 구현한다.
- 방문 종료일이 지났다고 접근을 자동 종료하지 않는다. 귀국 후 케어를 위해 명시적 배정 해제 또는 직원 계정 비활성화 시 종료한다.
- 예약 번호·금액·보호자 연락처·원본 예약 JSON은 응답에 포함하지 않는다. 기존 예약 관리자의 권한 조건은 변경하지 않았다.
- 레벨·교재·수업 기록·리포트는 아직 이 화면에 구현하지 않았다. 다음 단계에서 방문에 연결한다.

## 저장과 권한

`care_assignment_events`는 방문·교사 쌍의 배정/해제 이벤트를 추가만 한다. 최신 sequence가 현재 상태이며 이전 이벤트를 수정하거나 삭제하지 않는다. actor_id와 시각도 함께 기록한다. 학생별 방문 이력은 유지된다.

서버 세션에서 확인한 직원 ID로 get_care_roster/set_care_assignment를 호출한다. 두 함수는 SECURITY INVOKER, 빈 search_path, service_role 전용이다. DB에서도 직원 활성 상태와 역할을 다시 확인한다. 현지 선생님의 조회 범위는 DB 쿼리에서 제한한다. 클라이언트에 전체 목록을 주고 숨기는 방식이 아니다.

변경은 관리자만 가능하며 활성 local_teacher 계정만 새로 배정한다. 비활성 교사의 기존 배정은 해제 가능하다. 방문·교사별 잠금과 이전 이벤트 ID 비교로 오래된 화면의 변경을 거절한다. 요청 ID 재시도는 같은 이벤트를 반환하고 다른 내용으로 재사용하면 거절한다.

기존 bookings/students 등의 광범위 DB 정책은 아직 별도 전환 과제다. 신규 API 권한 검증이 기존 전체 서비스의 접근 통제 문제까지 해결했다는 의미는 아니다.

## 검증과 배포 상태

- 새 마이그레이션 `20260912061214_student_care_teacher_assignments.sql`은 **로컬 파일만 작성했고 운영에 적용하지 않았다**. 사용자의 통합 배포 결정에 따른다. 운영 DB를 사용하는 로컬 서버에서도 로그인 후 해당 함수 호출은 마이그레이션 적용 전까지 503이 예상된다.
- 가상 자료만 넣은 격리 PostgreSQL(PGlite)에서 배정, 재방문 분리, 해제/재배정, 비활성 계정, 권한, 중복 요청, 오래된 변경 거부를 검증했다. 운영 학생·계정은 생성/수정하지 않았다.
- 신규 DB/API 테스트 11개 통과. TypeScript 검사 및 신규 파일·학생 연결 화면 ESLint 통과.
- 공통 메뉴를 추가한 기존 관리자 layout의 set-state-in-effect 2건과 현지 hub의 no-html-link-for-pages 4건은 변경 전 HEAD에서도 재현된다. 이번 메뉴 추가와 별개로 통합 배포 전 정리한다.
- 실제 브라우저에서 비로그인 시 로그인 안내와 학생 정보 미표시 확인. 실제 계정의 전체 화면 동작, 작은 화면, 교사 교체의 화면 갱신 검증은 통합 테스트 환경에서 추가로 수행해야 한다.
- 통합 배포 전 마이그레이션 적용 순서, 실제 활성 직원 역할, 기존 로그인/예약 회귀 검증, 직원 공지 중복 여부를 확인한다. 이번 단계에서는 배포나 공지를 하지 않는다.

검사 명령:

```powershell

```
