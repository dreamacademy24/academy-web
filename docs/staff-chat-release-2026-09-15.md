# 직원 채팅과 기존 업무 연결

전체 채팅과 직원 간 개인 채팅을 기존 Team Manager 안에 추가한다. 일반 업무와 데일리·주간 체크, 타임라인, 기존 댓글·완료·공지 읽음 기록은 변경하지 않는다.

- 문자, 사진·파일(개당 3MB, 최대 10개), 답장, 직접 언급, 읽음, 대화 검색.
- 업무·예약을 검색해 최대 5개 요약 카드로 공유. 비밀 업무는 수신자 권한에 따라 숨긴다.
- 메시지를 기존 업무에 연결하거나 기존 업무 작성 화면으로 새 업무 등록. 업무 관계자에게 선택한 메시지·첨부가 공유됨을 표시한다. 개인 대화 전체는 참가자만 접근한다.
- 홈과 메뉴에 미확인 메시지 수를 표시한다. 개인 메시지·직접 언급만 기기 푸시 대상으로 삼고, 전체 일반 메시지는 반복 푸시하지 않는다.
- 입력은 이 브라우저 탭의 세션 저장소에 보관한다. 재전송 UUID와 방별 DB 잠금으로 중복 및 읽음 역행을 막는다.
- 사진은 기존 최적화 함수를 재사용한다. 첨부는 비공개 버킷에 저장하고 직원 세션 및 대화·연결 업무 권한을 검사한 API로 제공한다.

## 검증

- API 단위 검증: 현재 활성 직원 권한, 수신 대상, 작성자 위조 방지, 사적 대화 차단, 중복 연결, 첨부 소유권.
- DB 트랜잭션 후 롤백: 중복 전송, 같은 방 답장, 읽음 역행 방지, anon 테이블·RPC 접근 금지. 운영 기록을 변경하지 않는다.
- 실제 클라이언트 + 실제 API 핸들러의 분리된 브라우저 테스트: 전체/개인 대화, 언급, 답장, 검색, 업무 연결, 새 업무 작성 연결, 업무/예약 가져오기, 초안 유지.
- 실제 직원 역할의 임시 계정으로 로그인·HTTP·DB·비공개 파일 저장을 검증. 테스트 계정끼리의 개인 대화만 사용하고, 생성한 비공개 업무·메시지·파일·계정만 삭제한다.
- Next.js 전체 빌드 통과. 운영 배포 후 동일 HTTP 검증과 실제 공개 자산 확인 필요.

## 알림과 후속 범위

웹푸시는 브라우저/OS 알림 허용과 VAPID 설정이 필요하다. 지원되는 기기는 화면 밖에서도 받을 수 있으나 절전·집중 모드·브라우저 강제 종료 등에 따라 전달이 제한된다. iPhone/iPad는 웹푸시를 지원하는 홈 화면 웹 앱에서 사용한다. 전달 실패는 채팅 저장을 취소하지 않는다. 미확인 수는 DB에 남는다. 기기별 실제 푸시 수신은 사용자 기기 권한 허용 후 검증해야 한다.

이 변경은 채팅·업무 연결 단계다. 예약별 담당 완료, 각자 완료, 공동 결과의 최종 확인자 제안·수락, 공유 읽음 방식 분리는 이 코드에서 완료한 것으로 표시하지 않는다. 기존 체크리스트를 새로 만들지 않고 해당 동작을 별도로 변경·검증해야 한다.
