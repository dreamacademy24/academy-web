# 드림아카데미 통합 학생 케어 실행 계획

## 목적과 상태

연수 전 사전 인계 → 현지 수업 → 방문별 리포트 → 귀국 후 드림이 복습 → 교사 피드백·화상 리뷰 → 재방문으로 이어지는 공통 학생 기록을 만든다.

완료 표시는 검증된 결과에만 사용한다. 이 문서는 실행 순서를 확정하는 작업 목록이며 운영 배포·데이터 통합 완료를 뜻하지 않는다.

현재 로컬 학습 시안: 게스트/학습 입구, 나무집 이야기, 단어 듣기·그림 찾기·매칭·철자·손글씨·녹음, 이야기 복귀. 기기 저장과 브라우저 음성 단계이며 계정별 서버 저장, 캐릭터 연기, 담당 교사 리뷰는 미구현. BR 표기 제거도 전체 산출물 점검 전이다.

## 01. 기존 시스템 조사 — 진행 중

- [x] 한국인 관리자, 현지 허브, 직원업무 HTML, iframe 연결 확인.
- [x] 한국인 예약 학생 탭과 현지 달력의 bookings.students 사용 확인.
- [x] 별도 학생 화면의 students 조회, bookings_new fallback 코드 확인.
- [x] 예약 등록이 students를 저장한 후 bookings.students에도 별도 저장하는 코드 확인: app/admin/bookings/page.tsx.
- [x] 영문 이름 수정도 두 저장 구조를 각각 갱신하는 코드 확인: app/api/portal/student-english/route.ts.
- [x] 현지 달력의 예약 ID+배열 순서 식별 방식, 포털 fallback의 null 학생 ID 확인.
- [ ] 배포 커밋과 현재 작업 코드 차이 확인. 다른 진행 작업을 함께 배포하지 않는다.
- [x] 운영 DB 스키마·권한·관계·중복 및 한쪽만 저장된 자료를 읽기 전용 집계로 확인. 실제 학생별 매핑 검토는 별도 진행. 개인 정보는 소스 코드나 문서에 복제하지 않는다.
- [ ] 학생 생성·변경·삭제·예약 변경 전체 경로 목록 및 영향 범위 작성.

완료 기준: 실제 데이터 기준과 변경 경로, 기존 기능 보존 목록을 확인한다. 코드만 보고 운영 DB에 특정 테이블이 없다고 단정하지 않는다.

## 02. 공통 학생·보호자·방문 구조

- [ ] 보호자와 자녀 1:N 연결, 학생 고유 ID, 예약과 별개인 방문/수강 이력 정의.
- [ ] 방문마다 연수 기간, 담당자, 당시 레벨·교재·판본·수업 범위를 저장한다. 숙박 기간과 실제 수업 기간을 구분한다.
- [ ] 레벨/교재 변경 적용일과 이전 상태를 보존한다.
- [ ] 동일 이름 자동 병합 금지. 기존 학생 후보 확인, 확정 매핑, 되돌릴 방법 마련.
- [ ] 테스트 자료로 형제자매, 재방문, 연장, 교사 변경, 동명이인을 확인한다.

완료 기준: 같은 아이의 여러 방문과 두 아이의 각 기록이 섞이지 않는다.

## 03. 계정·권한·언어 기준

- [ ] 현재 관리자 로그인, 현지 로그인, 직원업무 세션 연결 분석.
- [ ] 예약 담당, 학습 관리자, 교사, 현지 운영, 보호자 역할과 읽기/수정/발행 범위 정의.
- [ ] 공통 로그인 및 서버의 권한 검사 적용. 메뉴 숨김으로 권한을 대체하지 않는다.
- [ ] 예약·결제·상담 원문, 내부 지도 메모, 공유 지도사항, 보호자 공개 피드백을 구분.
- [ ] 한국어/영어 UI와 기록 원문·번역을 구분. 번역 검토 상태 및 수정 기록 설계.

완료 기준: 계정을 바꾸거나 직접 URL/API로 접근해도 허용 범위만 접근한다.

## 04. 기존 자료 연결과 전환

- [ ] 기존 학생·예약의 매핑 미리보기 및 불일치 목록 생성.
- [ ] 백업, 되돌리기, 중복 연결 방지, 재실행 가능성 확보.
- [ ] 공통 학생 조회/변경 경로를 만들고 기존 화면이 점진적으로 사용하게 한다.
- [ ] 두 곳을 각각 저장하다 한쪽만 성공하는 경로를 원자적 저장 또는 실패 복구 가능한 방식으로 전환.
- [ ] 기존 학생 목록·예약·달력·포털 결과를 비교하고 데이터 누락 확인.

완료 기준: 기존 기능의 학생 표시를 유지하며 영속 학생 ID로 연결된다.

## 05. 공통 학생 관리 화면

- [ ] 한국인 홈과 현지 홈에서 동일한 학생 상세 화면으로 진입.
- [ ] 예정/연수 중/귀국 후/재방문 학생 필터와 담당 교사 검색.
- [ ] 기본 정보, 사전 지도사항, 방문 이력, 교재·수업, 평가·리포트, 복습·리뷰 탭.
- [ ] 현지 홈의 내 담당 학생 및 수업 전 인계 카드.
- [ ] 담당 교사 배정 기간과 변경 이력, 달력에서 학생 상세 바로 연결.

완료 기준: 현지 교사가 수업 전에 이전 방문과 이번 요청을 확인할 수 있다.

## 06. 수업·교재·레벨·코멘트

- [ ] 정식 단계 DSL-F2, DSL-T1, DR-F1, DR-F2, DR-S, DR-T 등록. 진급 조건은 별도 확정.
- [ ] 반 구분, 영어 능력 수준, 교재 단계를 서로 다른 필드로 관리.
- [ ] 교재 배정과 실제 수업 완료를 구분하고 주차·단원·페이지를 저장.
- [ ] 강점·어려운 점·다음 지도·일반 코멘트를 날짜와 작성 교사별 누적.
- [ ] 교사 변경 시 인계, 한국인 담당자의 보호자 상담 공유 항목 연결.

완료 기준: 누가 어느 방문의 어떤 수업에 남긴 기록인지 추적한다.

## 07. 학생 리포트

- [ ] 제공된 2페이지 형식 기반의 4영역 주차 점수, 그래프, 영역별 교사 의견 입력.
- [ ] 각 100점/총 400점 자동 합계, 미평가와 0 구분, 8주로 기간 제한하지 않음.
- [ ] 원본 총점 불일치 및 해석표 누락·경계 중복은 평가 기준 확정 후 처리. 임의 등급 산정 금지.
- [ ] 초안 → 검토 → 발행, 발행본 스냅샷·수정 버전·원본 PDF 보존.
- [ ] 이전 방문 비교와 보호자 공개, PDF 출력의 잘림/페이지 넘침 확인.

완료 기준: 당시 교재·수준·점수·의견이 나중 변경에 덮이지 않는다. 상세는 student-report-system-design.md 참고.

## 08. 직원 홈 통합

- [ ] 오늘 / 학생·학습 / 수업·일정 / 직원업무 / 현지 운영 / 예약·정산으로 메뉴 정리.
- [ ] 역할별 홈과 한국어/영어 표시. 예약 관리 권한과 수업에 필요한 예약 결과 공유는 분리.
- [ ] 기존 달력·공지·업무·티쳐 공유 기능 재사용. iframe 의존은 기능별 점진 해소.
- [ ] 기존 진입 주소, 즐겨찾기와 설치 앱 경로 호환 유지.
- [ ] 업무 완료 상태·공지 읽음 보존, 기존 안내서 재게시/반복 확인 업무 추가 금지.

완료 기준: 사이트를 오가며 같은 학생을 다시 찾을 필요가 줄고 기존 업무도 동작한다.

## 09. 학습 앱 계정 연결

- [ ] 게스트(신청용)/학습모드 입구 유지. 보호자 계정에서 자녀 선택 및 현재 아이 표시.
- [ ] 학생·방문·교재·활동별 진도, 녹음, 손글씨를 서버에 저장.
- [ ] 기기 저장 시안 기록은 소유 학생 확인 없이 실학생 기록으로 자동 이전하지 않는다.
- [ ] 업로드 실패·재시도·중복 제출·아이 전환 중 녹음 처리 및 저장 상태 안내.
- [ ] 실제 수업한 단원과 담당 교사가 지정한 복습만 정확하게 연결.
- [ ] 다른 기기에서 이어하기와 형제자매 기록 분리 확인.

완료 기준: 교사가 확인할 수 있는 학생별 제출물이 서버에 남는다.

## 10. 드림이 이야기·교재 공동 설계

- [ ] 캐릭터 설정, 모험 세계, 단계 지도, 각 이야기 목표를 먼저 문서화.
- [ ] 기본 학습 → 이야기 연습 → 마지막 게임 확인 → 복습 구조.
- [ ] 승인 교재와 인물·단어·문장·사건 일치 검토. 내용 변경은 앱과 책에 함께 반영할 설계 마련.
- [ ] 공개 앱 화면·책 표지/본문·메타데이터·배포 파일명에서 BR 표기 제거 점검.
- [ ] 느린 읽기와 듣기 반복, 조작 난이도와 영어 성취 분리.
- [ ] 높은 단계 게임 아이디어는 learning-game-ideas.md 유지. 초급에 모두 구현하지 않는다.

완료 기준: 장면별 대사·동작·학습 활동·성공 조건이 일관된 첫 이야기 설계 완성.

## 11. 첫 이야기 완성 및 마지막 게임

- [ ] 캐릭터·배경 자산과 실제 행동 애니메이션, 느린 음성·효과음 제작 및 연결.
- [ ] 발견/이동/노크 등 아이 행동으로 이야기 진행, 기존 듣기·매칭·철자·쓰기·녹음 유지.
- [ ] 마지막 게임에서 혼자 해결/힌트 후 해결/다시 연습 구분. 점수만으로 레벨 승급하지 않는다.
- [ ] 말하기로 통과하는 게임은 녹음 저장과 별개로 음성 인식·판정·실패 대체 경로 구현.
- [ ] 휴대폰·태블릿 터치, 작은 화면, 음성 권한, 움직임 감소, 재시작·저장 확인.

완료 기준: 시작부터 종료까지 실제 플레이 가능. 화면 확대만으로 완성 캐릭터 애니메이션이라 부르지 않는다.

## 12. 귀국 후 담당 교사 케어

- [ ] 확인할 녹음·쓰기, 학생별 취약 활동, 지난 피드백을 교사 홈에 모음.
- [ ] 교사 피드백 → 화상 리뷰 대상/일정 → 리뷰 결과 → 보충 과제 연결.
- [ ] 기존 화상 수업·출석 기능과 학생 ID 연결, 새 시스템 중복 구축 피함.
- [ ] 보호자에게 공개 리포트·진행 현황·다음 과제 제공. 보관/삭제 및 연수 종료 후 이용 범위 정리.

완료 기준: 귀국 후 제출 하나가 교사 확인과 다음 복습까지 연결된다.

## 13. 전체 검증·통합 배포

- [ ] 한 아이/두 아이, 재방문, 수업 기간 변경, 교사 교체, 이전 발행 리포트 보존 확인.
- [ ] 예약 생성/수정, 직원 업무·공지, 달력·출석 등 영향받는 기존 기능 검증.
- [ ] 사용자 결정: 개별 기능을 먼저 배포하지 않고 학생·직원홈·리포트·학습 연결을 함께 검증한 뒤 통합 배포. 변경별 되돌리기 준비.
- [ ] 직원 변경 배포 및 검증 후 기존 공지 중복 확인하고 [새 기능 안내]/[수정 안내] 일반 공지 게시. 기존 안내서·읽음·완료 상태 보존.

## 14. 높은 레벨 확장

- [ ] 단어 속 정답 찾기, 숨은 단어 퍼즐, 사천성식 조각 연결, 이동형 말하기 게임을 학습 목표에 따라 배치.
- [ ] app+ly 같은 철자 조각과 발음·형태소 학습용 분할을 구분.
- [ ] 실제 학생 사용 결과와 교사 관찰에 따라 난이도·복습 간격 조정.

## 현재 다음 작업

학생 연결 확정과 방문 이력 기반에 공통 학생 화면·방문별 교사 배정 코드를 추가했다. 아래 최신 진행 기록을 기준으로 한다. 다음은 방문별 공식 학습 단계·교재와 수업 특이사항 기록, 이후 학생 리포트이다. 개별 기능 배포는 보류하고 통합 검증 후 배포한다.

## 진행 기록 — 공통 직원 세션 및 연결 검토
- 공통 서명 쿠키 검증과 활성 직원 조회를 분리했다. 기존 예약 관리자는 korean_admin 조건을 유지한다.
- 현지 로그인 성공 시 서버 쿠키 발급, 현지 로그아웃 시 서버 세션 종료, 관리자 로그아웃 시 현지 화면 상태 정리.
- /staff/student-review 및 관리자 전용 /api/staff/student-review 작성. 원본 변경 없는 조회, 이름/예약 검색, 상태 필터, 페이지 이동, 대조 근거 제공.
- 원본 조회는 페이지 단위로 전체 수집하고 실패하면 일부 결과를 정상 결과처럼 표시하지 않는다.

## 진행 기록 — 로컬 로그인 연결 복구

- 사용자 화면의 TypeError: fetch failed를 진단했다. 제한된 실행 환경에서 Supabase health 요청은 EACCES, 제한 밖에서는 HTTP 200이었다.
- 3108 개발 서버의 PID와 부모가 Next.js 서버인지 확인한 후 해당 프로세스만 종료하고 네트워크 가능한 환경에서 숨김 실행으로 재시작했다. 운영 배포는 하지 않았다.
- 실제 계정 대신 존재하지 않는 진단 아이디로 한국인/현지 로그인 API 모두 HTTP 401(정상적인 자격 증명 거부)을 확인했다. 사용자의 비밀번호는 읽거나 바꾸지 않았다. 실제 계정 로그인 성공 여부는 별도 확인 필요.
- 두 로그인 API의 내부 오류 노출을 한국어/영어 안내와 503 응답으로 변경하고 네트워크/RPC 오류 시 쿠키 미발급 테스트 추가.
